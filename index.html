01 — Systems

Perception is the game

Every system is built around one idea: driving with incomplete, delayed, noisy information — and getting better sensors instead of better eyes.

01

Real LiDAR pipeline

Scan generator → environment raycasts → measurement processor (noise, dropout, reflectivity, weather) → latency queue → pooled point-cloud renderer. Occlusion is exact, not faked.

02

7 visualization modes

Point Cloud, Distance, Height, Intensity, Detection, Semantic and Wireframe. Advanced modes unlock through the research tree — each reveals a different layer of the same scan.

03

7 sensor tiers

From the LDR-100 BASIC at 60 m and 8 channels to the LDR-X EXPERIMENTAL at 280 m and 64 channels. Frequency, range, density, noise and latency all change how the world appears.

04

Autonomy that feels real

Six assistance levels consume only perception output. When road confidence drops, the car slows and stops. It never cheats with ground truth — it asks you to take over.

05

A living city

Six districts, traffic, trucks, pedestrians, traffic lights, rain, heavy rain, fog, dust, a day/night cycle and random dynamic events — all of which degrade the sensor physically.

06

Deep progression

Earn credits and research data, buy five vehicles, eight upgrade categories, auxiliary radar/camera/ultrasonic pods, and unlock the full autonomy stack.

02 — Under the hood

Five stages, one truth

The renderer never draws the world directly. Everything you see travels through the same pipeline a real sensor stack would use.

STAGE 01

Scan

Rotating azimuth and vertical channels produce a full 360° sweep at the sensor's rate.

STAGE 02

Raycast

Thousands of rays traverse a 16 m spatial hash of analytic boxes, cylinders, spheres and ground.

STAGE 03

Measure

Dropout, range noise, reflectivity, weather degradation and obstruction damage are applied.

STAGE 04

Delay

Points and object snapshots enter a latency queue; perception receives data milliseconds late.

STAGE 05

Render

A GPU ring buffer draws up to 450k points with age fade and mode-based colorization.

04 — Tech stack

Small stack, deep simulation

One runtime dependency, no art assets, no game engine. The simulation, renderer, UI and audio are all written from scratch.

Language
TypeScript — all simulation and game logic
Renderer
three.js 0.170 (WebGL 2) with a custom GLSL shader
World
Spatial hash + 2D DDA over analytic primitives
Perception
Custom tracker with confidence-gated classification
Autonomy
Pure-pursuit planner consuming perception only
Vehicle
Arcade bicycle model with battery, damage and regen
UI
Vanilla DOM/CSS + Canvas 2D — no framework
Audio
Web Audio API — fully synthesized, zero assets
Desktop
Electron 33 with context-isolated IPC save bridge
Build
esbuild 0.24 → single IIFE bundle
Packaging
electron-builder 25 — portable exe + NSIS installer
License
MIT — JohnLC Studios Open Source Softwares
Deterministic worldA seeded generator builds the same six-district city, road graph and prop layout every run — good for tests and reproducible scenes.
Adaptive ray budgetThe scanner measures milliseconds per ray and scales its per-frame budget toward a ~5 ms target, so low-end machines lose density instead of frame rate.
No cheating autonomyThe driving AI reads tracked objects and the road estimate, never true object positions. Uncertainty has consequences.
Assets optionalRain, wind, engine, scans and alerts are generated at runtime. The repository ships no audio files.
